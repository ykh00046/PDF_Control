## 1. 배경 (Why)

전 PDCA 문서(`NEXT_STEPS`, `PROJECT_STATUS`, `current-state.analysis`)에 걸쳐 반복적으로 등장하는 **#1 미해결 사용성 이슈**:

> "긴 텍스트가 매우 좁은 영역일 때 8pt까지 축소 후에도 삽입 실패 가능. 극단적 케이스에서는 영역 확장 또는 고정 폰트 크기 선택 필요."

### 현재 동작의 한계

`app/operations/applicator.py::_insert_text_with_autofit`는 텍스트가 박스를 넘칠 때 **오직 폰트 크기를 축소**한다(`TEXT_AUTOFIT` 바이너리서치 → 실패 시 `_insert_with_shrink`로 추가 축소). 박스 높이는 `원본 높이 + TEXT_BOX_Y_PADDING(12pt)`로 사실상 1줄 고정이다.

이로 인한 문제:

| 시나리오 | 현재 결과 |
|---|---|
| 한 줄짜리 원본을 긴 문장으로 교체 | 폰트가 6~8pt로 축소돼 **읽기 어려움** |
| 좁은 영역 + 매우 긴 텍스트 | 축소로도 안 들어가면 `text.overflow` → **글자 사라짐** |
| 가로로만 압축 | 세로 여백이 남아도 활용 못 함 |

`insert_textbox`는 **자동 줄바꿈을 이미 지원**한다. 단지 박스 높이가 1줄로 고정돼 줄바꿈된 텍스트가 높이를 초과(`result < 0`)해 실패할 뿐이다. 즉 **세로 공간을 쓰도록 박스 높이를 확장**하면 폰트 축소 없이 가독성을 유지할 수 있다.

> **정직성 노트**: "고정 폰트 크기 옵션"이 `NEXT_STEPS`의 1순위 제안이었으나, 이는 *증상 완화*(작은 글씨 강제)에 가깝다. 근본 해법은 **세로 공간 활용(워드랩)**이며 폰트 축소보다 가독성·정보 보존 모두 우수하다. 따라서 워드랩을 주 기능으로, 폰트 축소는 워드랩 후에도 안 들어갈 때의 폴백으로 재배치한다.

## 2. 목표 (What)

### 필수 (Must)
- **M1**: 텍스트가 한 줄에 안 들어가면 폰트를 즉시 축소하지 말고 **박스 높이를 아래로 확장**해 줄바꿈으로 수용한다.
- **M2**: 높이 확장은 **페이지 경계(및 아래쪽 후속 콘텐츠 침범 방지)** 내에서만 수행하고, 한계에 닿으면 기존 폰트 축소 폴백으로 자연스럽게 이어진다.
- **M3**: 워드랩 발생 시 사용자에게 비차단 정보 경고(`OpWarning`)를 남긴다 (`text.wrapped`).
- **M4**: Preview·Save 두 경로가 동일하게 동작한다(기존 `ApplyMode` 단일 경로 유지).

### 권장 (Should)
- **S1**: 줄바꿈에 필요한 높이를 폰트 메트릭(라인 수 × 줄 높이)으로 사전 계산해 과확장/미확장을 방지한다.
- **S2**: 신규 동작을 `config.py` 상수로 제어 가능하게 한다(워드랩 on/off, 최대 확장 비율, 줄 높이 계수).

### 범위 외 (Won't — 차기 사이클)
- Replace 다이얼로그에 사용자 토글 UI 추가 (이번엔 설정 상수 기본 on, UI는 후속)
- 위쪽/좌우 확장, 텍스트 박스 드래그 리사이즈
- 양쪽 정렬(justify)·하이픈네이션

## 4. 리스크

| 리스크 | 완화 |
|--------|------|
| 높이 확장이 아래 콘텐츠를 침범 | 페이지 rect 하단 + 설정 최대 확장 비율로 상한, 초과 시 폰트 축소 폴백 |
